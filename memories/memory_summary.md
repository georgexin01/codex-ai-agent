## User preferences

- Before meaningful changes, read relevant project Markdown and reconcile it with current source; if asked for “all .md”, do not call a front-door-only pass complete.
- Follow the requested scope exactly; a screenshot does not authorize adjacent styling/refactors. Verify the named route, label, or behavior.
- For bilingual work, update and validate every requested locale and generated output, not English only.
- When asked to create an artifact directly, create it rather than only explaining an existing dynamic alternative.
- For “hide every price”, scan source defaults, locale catalogs, and rendered output for all monetary variants.
- Treat browser/live tests that can create bookings, metrics, or records as state-changing; use safe fixtures and report unperformed gates.
- A “wait” / “skip that last request” instruction stops that request immediately.

## General Tips

- Current source/runtime/tests outrank historical documentation. Check Git status first and preserve unrelated dirty changes.
- Separate syntax/build/diff checks from HTTP, browser, Apache/host-rule, and production verification.
- On Windows, prefer short independently quoted PowerShell commands after complex quoting fails; use existing generators/scripts rather than fragile inline `php -r` commands.
- For missing tracked `.codex` content, compare `git ls-files` with the worktree and inspect both sparse-checkout configs before treating it as deletion; do not attribute recurrence to ChatGPT/VS Code without evidence.
- Reuse focused procedures when applicable: `skills/hierarchical-replica-chunking/`, `skills/zeta-bilingual-static-site/`, `skills/localhost-project-match/`, `skills/local-supabase-protection/`, and `skills/static-site-metadata-sweep/`.
